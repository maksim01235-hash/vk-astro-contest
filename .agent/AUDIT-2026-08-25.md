## 3. Находки

### 🔴 A1. Обход пароля админки при незаданной переменной окружения
**Где:** `src/app/admin/page.tsx:68` — `if (!ADMIN_PASSWORD_HASH || await verifyPassword(password, ADMIN_PASSWORD_HASH))`.
**Проблема:** если секрет `NEXT_PUBLIC_ADMIN_PASSWORD_HASH` не задан при сборке,
условие истинно на первом операнде → админка открывается с любым паролем.
Серверный аналог (`Code.gs`, `ADMIN_HASH_NOT_CONFIGURED`) сделан правильно —
фронтовый гейт должен вести себя так же.
→ **Задача 4 в TASKS.md.**

### 🟡 A2. Доступность карточек считается по клиентским часам
**Где:** `src/app/page.tsx` (`isReleased`) и `src/app/quiz/page.tsx:232`.
Дельту перевели на серверные часы, а гейт «замок/доступна» остался на локальных:
при смещении часов (реальный кейс −67 c зафиксирован) карточка открывается
позже/раньше положенного. Инфраструктура `serverClock` уже есть.
→ **Задача 5.**

### 🟡 A3. Crash-логи ErrorBoundary не доходят до таблицы
**Где:** `src/components/ui/ErrorBoundary.tsx` пишет только в буфер `logger.ts`;
буфер отправляется лишь вместе с ответом/фидбэком/кнопкой админа либо автосбросом
при 200 событиях. Крашнувшийся пользователь чаще всего ничего из этого не сделает.
→ **Задача 6** (экспорт принудительного сброса и вызов в `componentDidCatch`).

### 🟡 A4. Операционный риск: срок жизни VK_USER_TOKEN
User-токен для `wall.getReposts` живёт ~24 ч (`expires_in: 86399` — см. docs).
После истечения каждый ответ начнёт писать `repost_fail`, кнопка перепроверки —
`wall.getReposts[5/15]`. Хранение в Script Properties корректно (не на клиенте).
**Рекомендация владельцу:** ротация перед каждым днём конкурса; мониторить всплеск
`repost_fail` в Logs. В docs стоит добавить явное предупреждение о сроке.

### 🟢 A5. wall.getReposts без пагинации
`count=1000`, смещения нет: у поста с >1000 репостов «хвост» теряется → ложные false.
Для масштабов конкурса некритично, но дёшево закрывается циклом по `next_from`.
→ **Задача 8 (в составе инфраструктурных пунктов).**

### 🟢 A6. refreshReposts затирает «сиротские» строки
Ответы с `card_id`, которого нет в Cards (или без post_id), получают
`has_reposted=false` при batch-записи всей колонки. Решение владельца: сирот не трогать.
→ **Задача 9.**

## 4. Реестр принятых рисков безопасности (без изменений по решению владельца)

1. Пароль админки хранится публичным SHA-256-хешем в бандле; защита «от случайного доступа».
2. Apps Script endpoint опубликован как «Anyone»: возможна прямая накрутка
   Answers/Opens/Feedback чужими vk_id (подпись VK launch params не проверяется).
3. Feedback — без антиспама.
4. `VK_USER_TOKEN` — чувствительный long-lived токен на стороне сервера (допустимо);
   компрометация Script Properties = доступ к стене владельца. Scope только `wall`.

Миграция на проверку подписи launch params или серверный секрет — вне рамок текущего
этапа; возвращаться к вопросу при первых признаках злоупотреблений.
