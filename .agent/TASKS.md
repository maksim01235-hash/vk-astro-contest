## Задача 1. Отрицательная дельта из-за рассинхрона часов устройства и сервера

**Приоритет:** высокий. **Статус:** не начата.

### Симптом и доказательство
- `Answers`, строка id=33 (vk_id 13428976, card_id 3008): `delta_seconds = -36`,
  `open_timestamp = 2026-08-24T08:11:34.625Z` (= `Opens.first_open_timestamp`),
  `submit_timestamp = 2026-08-24T08:10:58.432Z`.
- Тот же физический момент по клиентским часам: событие `card_open` карточки 3008
  зафиксировано в `Logs` (последняя строка, vk_id 13428976) в `08:10:27.746`.
- Вывод: часы устройства отстают от часов Google ≈ на 60–67 секунд. Сервер проставил
  first_open «в будущем» относительно клиентских часов → дельта стала отрицательной.

### Причина
`openTime` приходит клиенту как ISO-строка, сгенерированная **сервером**
(`markCardOpen`), а `submitMs` считается по **локальным часам** устройства
(`quiz/page.tsx`, handleSubmit). При любом смещении часов пользователя дельта искажается
(вплоть до отрицательной). Пользователи с точными часами (все остальные строки Answers)
получают корректные значения.

### Что сделать
1. Новый модуль `src/utils/serverClock.ts`:
   - хранит измеренное смещение `offsetMs = serverIsoMs − clientNowMs` (модульная переменная);
   - `noteServerTime(iso: string, requestStartedAt?: number)` — обновляет offset
     (желательно компенсировать сетевую задержку: замерять время запроса и брать
     середину интервала);
   - `getServerNowMs(): number` = `Date.now() + offsetMs` (если offset ещё не измерен — просто `Date.now()`).
2. `src/lib/hooks/useCard.ts`: вызывать `noteServerTime(iso, startedAt)` при успешном
   `markCardOpen` и при успешном `sheetsApi.getServerTime()` (там уже есть ветка получения serverTime).
3. `src/app/quiz/page.tsx` (handleSubmit):
   - `submitMs = getServerNowMs()` вместо сырого `Date.now()`
     (офлайн-ветка может оставить локальное время — там сервер недоступен по определению);
   - защитный клэмп: если рассчитанный `delta_seconds < 0` — записать 0 и добавить
     событие `logEvent('api_error', { action: 'delta_clamped', ... })` для диагностики.
4. Офлайн-очередь (`STORAGE_OFFLINE_QUEUE`) не менять: там серверных времён нет by design.

### Критерии приёмки
- При искусственном смещении системных часов (тест вручную) дельта остаётся корректной и неотрицательной.
- Существующие сценарии не регрессировали: обычная отправка, ANSWER_DUPLICATE, офлайн-ветка.
- lint / tsc / build чистые.

## Задача 3. Репосты: убрать модалку, тихая проверка при отправке + полная перепроверка по вызову

**Приоритет:** средний. **Статус:** не начата.

### Решение владельца (обязательно к соблюдению)
Модалка RepostModal с кнопкой «Сделать репост» **удаляется из потока целиком**.
Система ТОЛЬКО проверяет факт репоста; никаких действий, побуждающих репостнуть,
в UI быть не должно.

### 3.1 Тихая проверка при отправке ответа
- `src/app/quiz/page.tsx`: убрать использование `RepostModal`, `useRepost`
  (хук можно удалить вместе с компонентом, если больше никем не используется)
  и связанные состояния/логи `modal_open type=repost`.
- В `handleSubmit` перед формированием `answer`: вызвать `sheetsApi.checkRepost(vkId, postId)`
  один раз; результат — в `answer.has_reposted`. При сбое проверки — `false` + различимое
  событие в лог (`repost_fail` уже существует; добавить поле причины).
- `marker_click`-подобного UX-шума не создавать: проверка не должна блокировать или
  задерживать отправку дольше, чем один запрос (таймаут общий).
- Не забыть: страница `/thanks` и `uiStore` — реестр модалок используется ещё и
  NotificationModal, store оставить.

### 3.2 Явная обработка незаданного service token
Сейчас `checkRepostViaVK` бросает `VK_SERVICE_TOKEN not set...`, клиент получает false
и молча показывает «репоста нет». Нужно:
- в `Code.gs`: при незаданных свойствах возвращать особую ошибку
  `REPOST_CHECK_NOT_CONFIGURED` (или ok:true c полем `configured:false` — на усмотрение
  агента, но формат должен быть однозначно разбираем на клиенте);
- на клиенте: логировать отличимое событие (например `repost_check_unconfigured`)
  один раз за сессию, чтобы в Logs было видно, что проверки фактически отключены;
- в `docs/google-sheets-setup.md` шаг 6 подчеркнуть как обязательный для боевого режима.

### 3.3 Полная перепроверка репостов по вызову (два пути)
Цель: пересчитать `Answers.has_reposted` по факту (пользователь мог репостнуть позже).

Бэкенд (`apps-script/Code.gs`):
- функция `refreshReposts(passwordHash)`:
  - проверка пароля админки: сравнение SHA-256 от параметра с `NEXT_PUBLIC_ADMIN_PASSWORD_HASH`
    (тот же механизм, что на клиенте админки; hash публичен — это защита от случайного доступа,
    осознанное решение проекта);
  - собрать уникальные `post_id` из Cards; для каждого — один вызов
    `wall.getReposts` (owner из Script Property `VK_OWNER_ID`, count максимум),
    построить Set репостнувших (`from_id`);
  - пройти Answers и обновить ячейку `has_reposted` только там, где значение меняется
    (точечные `setValue` или батч; LockService обязателен);
  - вернуть сводку `{ checked, updated, posts: [...] }`.
- POST-экшен `refreshReposts` в `doPost`, прокидывающий `body.passwordHash`.

Клиент:
- `API_ACTIONS.REFRESH_REPOSTS: 'refreshReposts'` в константах;
- метод `sheetsApi.refreshReposts(passwordHash)` — gate `'single'`,
  таймаут 30000 мс (добавить в `ACTION_TIMEOUT_MS`);
- кнопка на странице `/admin/stats` («Перепроверить репосты») рядом с AdminLogButton:
  берёт сохранённый пароль? НЕТ — пароль не хранится, поэтому кнопка открывает маленький
  ввод пароля (Input) и шлёт его значение; результат — toast со сводкой.
  Альтернатива, если окажется удобнее: кнопка на `/admin`. Выбор за агентом, но
  авторизация — только через явный ввод пароля, без использования STORAGE_ADMIN_AUTH
  как источника пароля.

### Критерии приёмки
- Ни одного появления RepostModal в UI; `has_reposted` заполняется при каждой отправке.
- При незаданном токене в Logs видно различимое событие, а не тишина.
- Кнопка перепроверки обновляет только изменившиеся строки и показывает сводку;
  повторный вызов идемпотентен.
- lint / tsc / build чистые.

**Критерии:** без секрета вход невозможен ни с каким паролем и видна понятная ошибка;

## Задача 6. Crash-логи ErrorBoundary должны доходить до таблицы

**Критерии:** искусственный кид ошибки в рендере → в листе Logs появляется строка
