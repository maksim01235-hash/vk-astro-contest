# Где какие данные хранятся (простыми словами)

Принцип системы: **сервер (Google Sheets) — единственный источник истины**.
На устройстве пользователя остаётся только минимум, без которого нельзя
работать офлайн или ускорить интерфейс. Старые локальные данные не могут
повлиять на работу: при несовместимых изменениях меняется версия префикса
хранилища, и ключи прошлых версий удаляются при первом запуске.

---

## 1. Google Sheets — основное хранилище

| Лист | Что хранит | Когда пишется |
|---|---|---|
| **Users** | Пользователи: VK ID, имя, дата регистрации, подписка на уведомления, активность | При каждом запуске приложения (`checkUser` создаёт/обновляет строку); при разрешении уведомлений (`subscribed = TRUE`) |
| **Cards** | Карточки конкурса + JSON-схемы блоков | Из админки (`saveCard`) |
| **Answers** | Ответы: кто, на какую карточку, время открытия/отправки, дельта секунд, сам ответ, сделал ли репост | При отправке ответа; дубль отклоняется сервером |
| **Opens** | Время **первого** просмотра карточки (пара vk_id + card_id) | При первом открытии карточки (`markCardOpen`); время записывается один раз и больше не меняется |
| **Logs** | Журнал событий: **одна строка на отправку** — `vk_id \| timestamp \| log`, где `log` — вся накопленная пачка событий одной JSON-строкой | Вместе с ответом/отзывом, автоматически при переполнении буфера (200 событий) или вручную из админки |
| **Feedback** | Отзывы пользователей | Из формы обратной связи |

Важно про время: дельта «сколько решал» считается на устройстве как разница
между моментом отправки и временем первого просмотра. Время первого просмотра
берётся с сервера, поэтому оно одинаково на всех устройствах пользователя.

## 2. localStorage браузера — только служебное

Все ключи имеют префикс с версией схемы: `vk_contest_v2_…`.

| Ключ | Что | Зачем нельзя убрать |
|---|---|---|
| `vk_user` | VK ID, имя, фото | Мгновенный автовход без ожидания ответа сети |
| `cards_cache` | Список карточек | Ускоряет повторное открытие главной. Живёт 2 минуты, потом удаляется |
| `card_open_<id>` | Резервная копия времени открытия карточки | Используется ТОЛЬКО если таблица недоступна (нет сети). Основное значение приходит с сервера |
| `offline_answers` | Очередь неотправленных ответов | Отправка при отсутствии интернета в момент нажатия «Отправить». Очищается после успешной синхронизации |
| `notif_dismissed` | Пользователь закрыл попап уведомлений | Чтобы не показывать попап тому, кто уже отказался. Решение о подписке живёт в таблице (`Users.subscribed`) |
| `admin_authed` | Флаг входа в админку | Удобство администратора |

Удалены по сравнению со старой версией: кеш репостов (`repost_*`),
локальные флаги «уже ответил» (`*_submitted`), флаги показа уведомлений
(`first_visit`, `notif_requested`). Их источники истины теперь на сервере.

## 3. Память браузера (теряется при закрытии)

- Буфер логов (до 200 событий) — уходит на сервер вместе с ответом или
  отзывом. Если лимит достигнут раньше отправки, буфер сбрасывается на
  сервер автоматически отдельным запросом (при сбое — повтор на следующем
  событии).
- Текущий пользователь и список отвеченных карточек (Zustand-сторы) —
  загружаются с сервера при каждом запуске.

## 4. Какие запросы уходят на сервер

**Запуск приложения**
1. `checkUser` — создать/обновить строку в Users.
2. `getAnsweredCards` — список карточек, где пользователь уже отвечал.

**Главная страница**
3. `getCards` — список карточек (если нет свежего кеша 2 минут).

**Открытие карточки**
4. `getCard` — данные одной карточки.
5. `markCardOpen` — зафиксировать/получить время первого просмотра.
6. `checkRepost` — проверка репоста через VK API (если пост задан).

**Отправка ответа**
7. `saveAnswer` — ответ + дельта + флаг репоста + весь буфер логов одним пакетом.

**Автосброс лога**
8. Если буфер достиг 200 событий до отправки ответа — `saveManualLog`
   отправляет накопленное отдельным запросом от имени пользователя.

**Обратная связь**
9. `saveFeedback` — отзыв + логи.

> **Про проверку Opens.** Запрос `markCardOpen` уходит при любой авторизации,
> пока настроен `NEXT_PUBLIC_SHEETS_API_URL` — в том числе в mock-режиме
> (запись создаётся от тестового пользователя с id `123456789`). Если API не
> настроен, пользователь не авторизован или нет сети — работает только
> локальный fallback, и строка в таблице не появится. Внутри VK на проде
> запись идёт от реального vk_id при первом открытии карточки.

**Офлайн**: если интернета нет в момент отправки, ответ попадает в
`offline_answers` и уйдёт через `syncOffline` при восстановлении связи.
Сервер отбрасывает дубликаты, поэтому повторная отправка безопасна.

## 5. Защита от устаревших данных

1. Клиентский кеш карточек живёт максимум 2 минуты.
2. Статус «Выполнено», подписка, репосты и время первого просмотра всегда
   читаются с сервера — локально они не хранятся вовсе.
3. При изменении формата хранения поднимается версия префикса
   (`vk_contest_v3_…` и т.д.), а ключи прошлых версий автоматически
   удаляются при первом запуске новой версии (см. `migrateLegacyStorage`
   в `src/utils/storage.ts`).
